## 1. 整体方案

该仓库采用**分层错误模型**，将错误严格区分为三类，并通过协议层统一序列化后返回客户端：

- **协议级错误（ProtocolError）**：定义在 `packages/protocol/src/schemas.ts`，使用 TypeBox schema 枚举出合法错误码 `version | busy | session_locked | not_found | invalid_request | not_implemented | internal_error`，并以 `{ code, message, details? }` 结构通过 `ResponseEnvelope.ok=false` 或 `ServerHelloError` 返回。
- **可跨边界的领域错误（PiServerError / SessionError）**：继承自 `Error`，携带强类型 `code` 字段，用于服务/会话层抛出，最终被转换为协议错误。
- **不可序列化内部错误（InternalServerError）**：仅保留 `cause` 用于上报日志，对外一律映射为 `internal_error`，不泄露堆栈。

此外，agent 层的 I/O 失败广泛使用 `Result<T, E>` 风格（如 `FileError`）配合 `fileResult()` 辅助函数，将结果式错误转换为 `SessionError` 后再向上传播。

## 2. 关键文件与包

| 文件 | 职责 |
|---|---|
| `packages/protocol/src/schemas.ts` | 定义 `ProtocolErrorCodeSchema`、`ProtocolErrorSchema`、`ResponseEnvelope`、`ServerHelloErrorSchema`，是所有跨进程错误的唯一契约 |
| `packages/server/src/errors.ts` | 定义 `PiServerError` 及其子类 `SessionBusyError` / `SessionLockedError` / `SessionNotFoundError` / `NotImplementedError`，以及 `InternalServerError` |
| `packages/server/src/server.ts` | 请求入口的 `handleRequest` 用 try/catch 捕获业务异常，调用 `toProtocolError()` 统一转为协议错误；`failProtocol()` 处理握手阶段错误 |
| `packages/agent/src/harness/session/types.ts` | 定义 `SessionErrorCode` 联合类型与 `SessionError` 类（`not_found | already_exists | invalid_entry | invalid_payload | invalid_lane | invalid_query | invalid_fork_target | storage`） |
| `packages/agent/src/harness/session/jsonl/errors.ts` | 定义 `JsonlDecodeError`（`syntax | schema`），并提供 `fileResult()` 把 `Result<T, FileError>` 提升为 `SessionError` |

## 3. 架构与约定

### 3.1 服务器端错误路由（server.ts）

```text
业务代码抛出 PiServerError / SessionError / InternalServerError
        ↓
handleRequest try/catch
        ↓
toProtocolError(error)
  ├─ instanceof InternalServerError → { code: "internal_error", message: INTERNAL_SERVER_ERROR_MESSAGE }
  ├─ instanceof PiServerError       → 直接映射 code/message/details（not_implemented 走常量消息）
  ├─ instanceof ProtocolValidationError → { code: "invalid_request" }
  └─ 其他未知错误 → reportError(原始 cause) + { code: "internal_error" }
        ↓
发送 ResponseEnvelope{ ok:false, error: ProtocolError }
```

握手阶段的协议违规（超时、非 hello 首帧、版本不支持）不走 Promise rejection，而是直接调用 `failProtocol()` 发送 `hello_error` 并关闭连接。

### 3.2 领域层 SessionError

`SessionError` 是 agent 子系统的统一异常基类，所有存储/编解码/分支操作都抛它。其 `code` 是受限字面量联合，便于调用方按语义分支处理（例如 `storage` 表示底层 I/O 失败，`invalid_entry` 表示数据损坏）。`JsonlDecodeError` 作为更细粒度的编解码异常，通常被上层包装成 `SessionError("invalid_entry", ...)`。

### 3.3 Result 模式

agent 的 JSONL 存储层返回 `Result<T, FileError>`，通过 `fileResult(result, message)` 在失败时构造 `SessionError` 并 throw，从而把“返回值”风格的错误提升到“异常”风格，让调用链保持统一的 `throw` 语义。

### 3.4 工具执行错误

`AgentTool.execute` 的文档约定“Throw on failure instead of encoding errors in content”，即工具实现应抛错而非返回 isError 标记，由 agent 循环捕获后以 `tool_execution_end` 事件 + `isError=true` 的形式通知上层。

## 4. 约定与约束

- **协议错误码必须来自 `ProtocolErrorCodeSchema`**：新增错误码需先在 schemas.ts 中声明，否则类型检查会拒绝。
- **PiServerError 的 code 必须是 `PiServerOperationErrorCode` 的子集**（busy / session_locked / not_found / invalid_request / not_implemented），禁止随意扩展。
- **内部错误不得暴露细节**：`InternalServerError` 的 `cause` 仅用于 `reportError` 上报，对外只返回固定消息 `INTERNAL_SERVER_ERROR_MESSAGE`。
- **未知异常一律降级为 internal_error**：`toProtocolError` 的默认分支记录原始错误后返回 `internal_error`，保证客户端永远收到合法的协议错误。
- **握手阶段不使用 Promise rejection**：所有握手期错误通过 `failProtocol()` 发送 `hello_error` 并关闭连接，避免未捕获的 unhandled rejection。
- **SessionError 的 code 是受限字面量**：新增状态码需在 `SessionErrorCode` 联合中声明，IDE 能提示遗漏分支。
- **工具实现不得吞掉异常**：`AgentTool.execute` 的契约明确要求抛错，而不是在 result 里编码错误信息。
- **错误传播路径单一**：业务层 → `PiServer.handleRequest` → `toProtocolError` → 协议响应，中间不自行构造 `ProtocolError` 对象。

## 5. 未发现的模式

- 仓库中未见 `try/catch` 之外的全局错误处理器（如 `process.on('uncaughtException')`）。
- 未见 `panic/recover` 模式（TypeScript 无 panic）。
- 未见统一的错误码常量表（错误码集中在 schema 和 Error 类的 `code` 字段中）。
- 未见基于 `zod`/`yup` 等运行时校验的错误分类（协议层使用 TypeBox schema 做类型约束）。
