## 简介
本指南面向安装、配置、网络与 API 调用失败等常见问题，提供系统化的排查步骤、调试技巧与日志分析方法。同时涵盖如何启用调试模式、查看更详细的运行输出、定位性能瓶颈、解读错误信息、复现问题并提交高质量 Bug 报告，以及社区支持与已知问题的临时方案与升级建议。

## 项目结构
本项目为多包工作区（monorepo），包含 AI 抽象层、Agent 运行时、编码 Agent CLI、TUI、协议与遥测等。根脚本统一构建与检查，CLI 入口负责初始化 HTTP 调度器并启动主流程；Agent 核心封装了消息循环、工具调用与事件处理；AI 层提供多提供商的统一接口与鉴权。

## 核心组件
- CLI 入口：设置进程标题与环境变量，屏蔽部分警告，并在加载全局/项目设置后配置底层 HTTP 调度器，再进入主流程。

- AI 提供商：通过 createProvider 注册提供商，集中管理 baseUrl、鉴权（环境变量读取）、模型清单与 API 适配。

## 详细组件分析

### CLI 入口与网络栈
- 作用：设置进程名、注入环境标志、屏蔽不必要的警告，并在 SettingsManager 加载完成后统一配置 undici 的全局调度器，确保后续所有 HTTP 请求走同一网络栈。
- 常见故障点：代理/证书/超时未正确配置会导致所有下游请求失败。
- 建议：优先确认代理、TLS 与超时参数是否正确；必要时在本地抓包验证出站流量。

### Agent 核心与错误处理
- 作用：封装 Agent 生命周期、消息与工具执行、重试上限、传输选择、流式回调与事件分发。
- 错误传播：当运行异常时，会构造一条包含 provider/api/model/usage/errorMessage 的消息事件，依次触发 message_start/message_end/turn_end/agent_end，便于上层统一捕获与展示。
- 可观测性：支持 onPayload/onResponse 回调，可用于记录请求载荷与响应头，辅助定位网络与鉴权问题。

## 性能考量
- 流式与回调：通过 onPayload/onResponse 可统计首字节时间、吞吐与错误率，用于定位慢请求与抖动。
- 重试与延迟：Agent 暴露 maxRetryDelayMs 以限制上游建议的重试间隔，避免雪崩。
- 并行工具执行：toolExecution 控制工具调用策略，合理设置可减少阻塞。
- 传输选择：transport 可影响连接复用与协议行为，结合网络环境调优。

## 故障排除指南

### 一、安装与环境问题
- 症状
  - 构建失败、类型检查报错、脚本无法执行。
- 可能原因
  - Node 版本过低或不满足要求。
  - 依赖未安装或缓存损坏。
  - 工作区脚本未正确执行。
- 解决步骤
  - 确认 Node 版本满足要求。
  - 使用工作区脚本进行清理、安装与构建。
  - 若离线构建，使用离线构建脚本以避免网络访问。
  - 使用检查脚本校验依赖锁定与导入规范。
- 参考
  - 构建与测试脚本、工作区定义、Node 引擎要求。

### 二、配置错误（API Key、baseUrl、模型）
- 症状
  - 鉴权失败、找不到模型、请求被拒绝。
- 可能原因
  - 环境变量缺失或拼写错误。
  - baseUrl 不正确或被代理拦截。
  - 模型清单与实际可用模型不一致。
- 解决步骤
  - 检查对应提供商的环境变量名称与值。
  - 用最小请求验证 baseUrl 可达与鉴权有效。
  - 重新生成或刷新模型数据后再构建。
- 参考
  - 提供商配置中鉴权与 baseUrl 的定义位置。

### 三、网络连接与代理
- 症状
  - 所有请求超时或连接失败。
- 可能原因
  - 代理/证书/超时未配置。
  - 企业防火墙拦截。
- 解决步骤
  - 在 CLI 入口处完成 HTTP 调度器的全局配置。
  - 通过抓包或 curl 验证出站流量与代理设置。
  - 调整超时与重试策略，观察是否改善。
- 参考
  - CLI 入口对 HTTP 调度器的配置时机。

### 四、API 调用失败（鉴权、限流、模型不可用）
- 症状
  - 返回 4xx/5xx、速率限制、模型不存在。
- 可能原因
  - 密钥无效或权限不足。
  - 超出配额或地区限制。
  - 模型清单过期或未发布。
- 解决步骤
  - 使用 onPayload/onResponse 记录请求与响应头，定位具体错误码与消息。
  - 降低并发或增加重试间隔，配合 maxRetryDelayMs 限制最大延迟。
  - 更新模型数据并重新构建。
- 参考
  - Agent 的 onPayload/onResponse 透传能力与重试上限。

### 七、错误信息解读与解决步骤
- 典型字段
  - errorMessage：人类可读的错误描述。

  - 根据 provider/api 判断是否为第三方限制。

  - 结合 onPayload/onResponse 的原始报文交叉验证。
